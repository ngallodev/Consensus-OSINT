## Suite comparison and risk

The suite runtime contract requires `tor` or `proxy-pool`, proxyctl route authority, explicit route configuration, `OSINT_REQUIRE_PROXY=1`, `OSINT_RUN_ID`, and remote DNS for Tor (`osint-suite/docs/OSINT_SUITE_RUNTIME_CONTRACT.md:7-23`). Suite tool builders and planner show distinct subprocess integrations and input-specific selection (`osint-suite/apps/pipeline/src/osint_tools.py:1-7,218-245,353-398`; `osint-suite/apps/suite/src/suite_planner.py:126-170,353-400`). The examined suite baseline `aadbb3c79cd2810144958c57f899546482a0c4e3` already includes a Consensus command builder and describes its routing (`osint-suite/apps/pipeline/src/osint_tools.py:431-433`; `osint-suite/docs/OSINT_SUITE_RUNTIME_CONTRACT.md:42-47`); its existence is not an acceptance or safety finding. See [capability matrix](capability-matrix.md), [network inventory](network-surface-inventory.md), and [risk register](risk-register.md).

**Static concern:** Consensus does not consume `OSINT_REQUIRE_PROXY` or `OSINT_RUN_ID` in the examined CLI/HTTP setup; absence of those references is limited by ignored/excluded code. Its HTTPX client does not set `trust_env=False`; without a configured proxy it constructs a client without an explicit proxy, which may use ambient settings (`consensus_osint/core/http.py:107-122`). This is a source-level compatibility concern, not an observed leak. Direct DNS and standalone AI/update/browser requests also require phase-specific route review. Do not treat a proxy flag as complete egress control.

The suite checkout `/lump/apps/osint-suite` was read-only. Its final observed porcelain contained untracked `.codewhale/`, `.mcp.json`, `docs/current-status/openspec-simplification-handoff-20261104.md`, `enzohehe1_report.json`, and `open`; these paths were not altered.
